# 可选论据资料表

2026-11-11起，所有此类资料表参照用户原件采用 [统一三列格式](material-table-format.md)：A4竖版、单表按资料类型分组，列名为“可用资料摘要”“资料来源”“可核验链接”，表后附“怎么用”“风险提示”。进攻、防守、证明保留为用途标签，同一条不重复展开成多张表。可填写结构见 [模板](../templates/material-table-template.md)。

资料表是成稿后的独立备赛附件。它整理本次写稿时实际检索、阅读并核验的论据，包括已用入稿和因篇幅未用入稿的相关材料；不输出内部思考链、逐步推演、检索日志或私有提示词。

## 何时提供

先交付已保存、重开检查非空的一辩稿 DOCX，保留原有桌面提示，再询问一次：

“是否将本次检索中已核验的论据，按参考样式整理成三列资料表，并注明进攻、防守、证明用途？”

用户明确选择“需要”“整理”等后再生成；明确不要则结束，未回复不视为同意。用户已要求同时生成资料表时，完成稿件后直接整理，不重复确认。同一成稿不重复询问；脚本已打印选项时，助手也不再重复。

离线预览、生成失败、拒绝覆盖、纯 API 测试或资料查询不触发该选项。选择前不建表或创建资料表文件，不为该选项额外调用模型或扩大检索。选择后优先复用本次已核验材料；确需补充核验时如实标明结果，不把未查证线索填作已核验论据。

## 用途与内容

| 分类 | 整理目的 |
|---|---|
| 进攻 | 针对与本题相关、可检验的竞争主张，指出其条件、机制或事实上的薄弱处，并给出对应证据；不编造对方已经说过的话。 |
| 防守 | 针对本方论点可能受到的具体质疑，列出回应所需依据及适用边界；“可能质疑”须按假设标明。 |
| 证明 | 直接支持本方定义、判断标准、核心论点或因果机制，说明证据支持哪一步。 |

同一论据可以有多个用途，保留同一编号，摘要中注明用途标签。资料类型用 `group` 显式指定，例如学理、实证、政策制度；未指定用“相关资料”，不靠模型猜测资料类型。每条列明论据核心、核验材料、用途与支持关系、适用条件与局限、简短核验说明，以及来源作者或机构、标题、日期和完整链接。核验说明只记录公开证据的核对结果与转引情况，不记录内部推演。

学理须解释命题及适用条件；案例须核对对象、时间、经过和结果；数据须保留统计口径、范围和时间。样稿、录音转写、AI 总结和只有标题的检索条目不能自动当作事实来源。无法核验或与本题无关的材料不收入表中，不为三个类别凑数。某类没有合格材料时写“本次未找到可核验的相关论据”；全部缺失时说明缺口，不生成空表冒充完成。

资料表单独保存，攻防内容不回写成稿；稿件正文仍不含预设反驳。只收录公开可核验的论据，不包含密钥、私人聊天或用户未授权公开的信息。

## Word 导出

将核验完成的材料整理为本机 UTF-8 JSON 对象，顶层为 `arguments` 数组，每项字段如下：

| 字段 | 要求 |
|---|---|
| `id` | 非空且唯一的论据编号，多用途沿用同一编号 |
| `categories` | 数组，值为“进攻”“防守”“证明”中的一项或多项 |
| `verified` | 布尔值 `true`；由整理者实际完成核验后标注 |
| `claim` | 论据核心 |
| `material` | 已核验事实、学理或案例的简述 |
| `usage` | 用途及对判断的支持关系 |
| `limitation` | 适用条件、统计口径或局限 |
| `verification_note` | 对公开证据的简短核对结果；必要时标明转引 |
| `sources` | 非空数组，每个来源含 `author`、`title`、`date`、`url` |
| `group` | 可选，本次实际资料类型分组；不提供时为“相关资料” |
| `sources[].link_label` | 可选，链接短显示文字；真实超链接目标仍使用完整 `url` |

来源网址须为实际核对过的 HTTP/HTTPS 链接；来源未标日期时填写“未标注日期”，不猜测日期。导出脚本仅检查字段与文件，不联网核验事实，`verified: true` 不能代替整理者查证。

在项目根目录执行：

```powershell
python skills/一辩稿DOCX输出/scripts/export_argument_table.py --topic "实际辩题" --side 正方 --input "verified-arguments.json"
```

默认保存到 `<系统实际桌面>/products/<用户实际完整辩题>-正方或反方-论据资料表.docx`，与稿件平铺存放。只清理文件名非法字符，不改写辩题；同名文件默认不覆盖。需要自定义目录时用 `--products-dir`，确认覆盖时才用 `--force`。临时 JSON 不作为最终交付，也不写入技能包或公开仓库。

保存后重开确认三列、分组、条数和真实超链接完整，并渲染检查分页，再显示资料表文件路径。用途和条件按编号保留在摘要、“怎么用”或“风险提示”中；不重复显示“是否整理资料表”的选项。
