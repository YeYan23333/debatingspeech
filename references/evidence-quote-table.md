# 攻防稿原文资料表：输入与核验规范

使用 `skills/一辩稿DOCX输出/scripts/debate_workflow.py --stage attack-defense --evidence-file evidence.json`。

## 提供什么

输入 UTF-8 JSON，顶层键为 `evidence`，每项：

| 字段 | 含义 |
|---|---|
| `id` | 唯一编号 E1、E2 等，用于正文指向表格 |
| `claim` | 这条资料实际支持哪项判断；不可超出原文 |
| `quote` | 从**已阅读原文**逐字摘录的短句；每个 URL 一条、中文不超过45汉字、英文不超过25词 |
| `url` | 原文所在的完整 HTTP/HTTPS 网址；应尽量直达原始材料 |
| `title` / `author` / `date` | 标题、作者/机构、发布日期；未标注日期时说明 |
| `usage` | 进攻/防守/证明等可用用途 |
| `encounter` | 哪个可能交锋需要它；未见实际对手说法应标为假设 |
| `limitation` | 样本口径、时间、论证边界与不能支持的更广判断 |
| `verified` | 人工完成来源真实性核对后才写 `true` |
| `quote_confirmed` | 人工逐字比对原始来源后才写 `true` |

导出脚本只验证字段类型、URL 结构、重复 URL 和短引长度，**不能联网确认** `verified: true` 的真实性。用户必须检查来源链接是否可访问、原文是否确有该句、语境是否一致、时间是否仍适用。不要把搜索摘要、AI 生成的引文或从第三方辩论稿转述的统计直接当作原文。优先选原始研究或原始公开记录。

未提供经人工核对的材料时，攻防 DOCX 会保留“待补可核验资料”的明确提示，不会生成虚构的引用表。

## 匿名模板

见 `templates/evidence.example.json`；其条目是字段示例，**不是**可用证据。要获得真实表格，先将核验过的来源填入 JSON，再运行命令。
