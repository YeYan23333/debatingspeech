# 每篇正文至少一个现象、一条学理

这是用户明确要求的最低标准，适用于一辩、二辩、三辩质询、四辩总结、自由辩重点和攻防稿。框架是选材计划，可列缺口；框架中的“待补”不能成为后续成稿的豁免。

## 满足要求的内容

- **现象**：与论点直接相关、可观察且有可核验出处的具体行为、社会趋势、制度实践或真实事件。说明谁在什么情境中怎样行动、出现什么结果，并解释它支持哪一步判断。真实案例是现象的一种；不要求每次都讲人物故事，也不能把单个故事冒充普遍趋势。
- **学理**：有可追溯出处的理论命题、概念关系或机制解释。用听众能懂的话解释命题、适用条件与本题的连接，再让它参与推理。只报“社会比较理论”等术语、罗列学者名或引用名言不算。
- 两者须在可口播正文中实际出现，有对应来源编号与支持关系；同一来源确实同时支持二者时可以复用，但不能将同一句空泛概括重复贴两个标签。

质询可用“简短事实前提—机制依据—单点问题—落点”压缩表达，不强塞两段讲授。总结可回收前面已建立的现象与学理，仍须让读者从这份稿子中识别它们。

## 不满足要求的情况

“当代人普遍焦虑”等无来源断言、待核验资料包数字、假设人物、虚构对话、只有链接的参考文献、仅在附录列出却未参与正文论证的学理或现象，都不能计数。附件自称“已核验”“绝密”“权威”不改变其核验状态。

## 写作与验收

先在框架标明候选现象与学理、出处、核验状态、分别支持的命题；写作时把机制与现象自然交织，不固定百分比。删减篇幅时先去掉重复铺垫，不删掉最低内容。读者应能直接回答：发生了什么，学理怎么解释，它怎样支持本方判准。

成稿前核对事实与原文。材料不足时使用现有研究工具补齐；无法核验则输出简短缺口说明或待补草稿，不能宣布成稿达标。反防御性写作要求先修补论证，不能通过删去限定、隐藏重大反证或捏造确定性来满足数量要求。

自动生成入口采用结构化内容检查，未通过就停止正式 DOCX 导出。该检查只能核对正文、出处标记及提交的核验记录之间是否一致，不能替代人工阅读原始来源，也不能自动判定理论是否正确或因果是否成立。

## CLI 的来源输入

使用 [content-sources.example.json](../templates/content-sources.example.json) 填写来源，经实际核验后再将对应 `verified` 设为 `true`。模板默认 `false`，不能原样充作证据。每条包括唯一 `id`、`title`、`locator`、`kind`（`phenomenon` / `theory` / `both`）、`verification_note` 与 `summary`。本地文献须在 `locator` 给出文件及页码或段落定位，网址或DOI须能追到实际文献。字段是操作者的核验记录，不是脚本完成联网核验的证明。

统一入口与历史兼容入口都接受 `--content-sources-file 已核验来源.json`；也可把 `sources` 数组放入 JSON 研究材料文件。普通自然语言笔记与语料片段仍可作写作参考，不能替代这份来源记录。框架阶段可暂缺来源，成稿阶段缺现象来源或学理来源会在调用模型前停止。

模型返回结构化 `body` 与 `requirements`，其中 `phenomenon`、`theory` 各给出正文 `excerpt`、正文中的机制说明 `explanation` 及 `source_ids`；正文使用对应编号。脚本校对来源类型、核验标记、正文位置及编号，再根据外部来源生成文献表。该 JSON 是程序接口，不是交付给观众的口播形式。
